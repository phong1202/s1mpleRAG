# Phase 1 — Ingestion Build Plan

**Scope: upload and process PDFs.** Ends with real embeddings in `parent_chunks` and `child_chunks`.
Retrieval (`app/core/`, `POST /query`) is Phase 2 and is not built, not stubbed.

Design reference: `system-design.md`. Where this plan and that document disagree, the design document
is authoritative.

---

## Scope boundary

| In | Out (Phase 2) |
|----|---------------|
| Presigned upload → MinIO | `app/core/retriever.py` |
| Register + dedup + publish | `app/core/context_builder.py` |
| S1 Parse (PyMuPDF + Docling) | `app/core/generator.py` |
| S2 Structure (sanitize + chunk) | `POST /query` |
| S3 Enrich (metadata + context) | `query_controller.py` / `query_service.py` |
| S4 Embed | The `DISTINCT ON` retrieval SQL |
| S5 Persist | Citation assembly |
| Status polling endpoint | |
| DB-level similarity **test** | |

**No Phase 2 scaffolding.** No empty `app/core/` package, no placeholder router, no unused schema
classes. The directory does not exist until Phase 2 begins.

## Step 1 — Infrastructure and shared clients

**Adds:** `docker-compose.yml` services (`rabbitmq`, `redis`, `minio`), `shared/storage.py`,
`shared/rate_limiter.py`, `shared/embeddings.py`, config additions.

`shared/` is a **sibling of `app/`**, not inside it — the worker must never import a module that pulls
in FastAPI, and package layout is a more reliable boundary than discipline.

- MinIO buckets `raw` and `staging` created on startup (init container or client-side ensure).
- `staging` gets a 7-day lifecycle rule.
- Token bucket as a Lua script, four keys: `rl:openai:{chat,embed}:{rpm,tpm}`.

**Done when:** an integration test reaches all three containers — puts and gets an object, acquires and
exhausts a bucket, embeds a string and gets 1536 floats back.

**Watch for:** MinIO's endpoint differs inside Compose (`minio:9000`) versus from the host
(`localhost:9000`). Presigned URLs are signed for a specific host — a URL generated for the internal
name is unusable by a browser. Configure the public endpoint separately from the internal one.

## Step 2 — Schema migration

**Adds:** `app/models/{document,parent_chunk,child_chunk}.py`, one Alembic revision.
**Breaks:** the scaffold's document CRUD.

Per design §5.1: `documents.title` / `content` / `embedding` are dropped, file-level columns added,
two tables created. Migration generated by `alembic revision --autogenerate`, never hand-written; the
`CREATE EXTENSION` line is already in the initial migration, so this one only adds tables.

**Test fallout — expect this, don't fight it.** The ~10 tests covering `POST/PATCH/DELETE /documents`
with a JSON title/content body are **deleted**, not adapted; a document is created by uploading a PDF
now. The ~45 infrastructure tests (config, logging, middleware, exception handlers, envelope,
transaction boundary) are untouched and must stay green throughout.

**Done when:** `alembic upgrade head` succeeds, `\d child_chunks` shows `embedding vector(1536)` and
the HNSW index, and the surviving suite is green.

**Watch for:** the model classes are **shared with the worker**, so they must not import anything
async. Keep them pure declarative — session handling lives in `app/utils/database.py` (async) and
`worker/db.py` (sync) separately.

## Step 3 — Ingestion API

**Adds:** `ingestion_controller.py`, `ingestion_service.py`, reworked `document_repository.py`,
document schemas.

```
POST /documents/upload-url    → presigned PUT + object_key
POST /documents               → 202 {document_id} | 409 duplicate
GET  /documents/{id}/status   → status, stage, attempts, failed_stage
GET  /documents               → list, filter by status
```

Registration is the atomic dedup from design §8:

```sql
INSERT INTO documents (sha256_hash, ...) VALUES (...)
ON CONFLICT (sha256_hash) DO NOTHING RETURNING id;
```

**Publish to the broker only on a returned row.** That single rule makes enqueue exactly-once per
file without a distributed lock.

**Done when:** upload a fixture PDF via presigned URL, `POST /documents` returns 202, the row is
`QUEUED`, a message is visible in the RabbitMQ management UI, and re-posting the same hash returns
409 with no second message.

**Watch for:** the client-supplied `sha256` must be **re-verified server-side** against the stored
object before registering. Trusting it lets one client poison another's dedup entry.

## Step 4 — Celery skeleton with no-op stages

**Adds:** `worker/celery_app.py`, `worker/stages.py` (five tasks that log and advance state),
`worker/db.py` (sync engine), worker services in Compose.

This step deliberately builds **no real processing**. It proves routing, chaining, `acks_late`,
retry/backoff, and the state machine while every stage is trivially debuggable. Skipping it means
debugging RabbitMQ semantics and Docling inference simultaneously.

- `task_routes` maps all five stages across `cpu` and `llm` queues.
- `worker-cpu` and `worker-llm` containers, per design §3.
- Each no-op stage updates `documents.stage` and returns.

**Done when:** posting a document drives `QUEUED → … → COMPLETED` with nothing but log lines, and
killing a worker mid-chain results in redelivery rather than a stuck document.

**Watch for:** `worker/db.py` uses `postgresql+psycopg://` (sync), deliberately different from the
API's `postgresql+asyncpg://`. Two engines, one set of models. Tasks are plain `def` — no
`asyncio.run()` anywhere in the worker.

## Step 5 — Docling service

**Adds:** `docling_service/` (its own Dockerfile, FastAPI wrapper, requirements).

```
POST /parse  { object_key, pages: [2, 7] }
→ { pages: [ {page, markdown, confidence} ] }
```

Pulls from MinIO itself — no multi-MB payloads over HTTP. Models load **once at process start**, never
per request. Concurrency 1.

**Done when:** `POST /parse` returns markdown for `tables.pdf`, and the container's memory sits flat
across repeated calls rather than climbing.

**Watch for:** first run downloads model weights — slow, and it will look like a hang. Bake them into
the image or mount a cache volume, or every `compose up` on a clean machine pays for it.

## Step 6 — S1 Parse + S2 Structure

**Adds:** `worker/parsing.py`, `worker/chunking.py`. Replaces two no-ops.

**S1:** guards (encrypted, oversized) → PyMuPDF fast pass → scanned detection
(`text_chars / pages < 100` → route everything) → per-page Docling routing → 90s per-page timeout with
raw-text fallback → `parsed.json`.

**S2:** sanitize (**skipping fenced code blocks**) → parent chunks 500–1000 tokens on heading
boundaries → child chunks 100–200 tokens carrying `page_number` → drop chunks under 20 tokens →
deterministic `chunk_index` → `chunks.json`.

**Done when:** every fixture produces sane `chunks.json`; `encrypted.pdf` lands in `DEAD_LETTER` with
a specific reason and no traceback; `scanned.pdf` routes all pages to Docling.

**Watch for:** `chunk_index` must be **deterministic** — same input, same indices, every run. It's the
natural key that makes S5 idempotent. Any nondeterminism here (dict iteration, a set, a timestamp)
silently breaks retry safety in a way that only shows up as duplicate rows much later.

---

## Step 7 — Rate limiter + S3 Enrich

**Adds:** `worker/enrichment.py`, rate-limiter integration in the task decorator.

Batches of 20 child chunks to `gpt-4o-mini`, structured output keyed by chunk id.

**Validation before any write** — the part most likely to be skipped and most costly to skip:

- response length == batch length
- every input id present exactly once
- `category` ∈ the closed enum

A bad batch retries **only the missing ids individually**. A chunk failing solo twice gets
`context = ""` and proceeds — a weaker context sentence beats a dead-lettered document.

Backpressure per design §12: `self.retry(countdown=wait_ms * jitter, max_retries=None)`. Both
conditions matter — without `max_retries=None` a busy afternoon dead-letters healthy documents;
without jitter, deferred tasks wake together and stampede.

**Done when:** a forced malformed LLM response (stub returning 19 of 20) triggers per-id retry rather
than batch failure, and a deliberately tiny bucket produces requeues rather than 429s.

**Watch for:** OpenAI caching is automatic and ~50%, not Anthropic's explicit ~90% (design §12).
Expect a higher per-document cost than the original architecture assumed. Fine at this volume;
documented so it isn't a surprise later.

## Step 8 — S4 Embed + S5 Persist

**Adds:** `worker/embedding.py`, `worker/persistence.py`.

**S4:** batches of 100 to `text-embedding-3-small`, `dimensions=1536`, **L2-normalize every vector**,
assert count and dimension, write `.npy` + manifest.

**S5:** one sync transaction — upsert parents, capture the id map, upsert children resolving
`parent_id`, mark `COMPLETED`.

**Done when:** a fixture PDF produces rows in both tables with non-null embeddings, and **running the
whole chain a second time changes nothing** — same row count, same ids.

**Watch for:** normalization is not cosmetic. `vector_ip_ops` assumes unit vectors; skip it and the
index returns wrong neighbors with **no error at all**. Assert it in code, not just in a test.

---

## Step 9 — Idempotency and retrieval smoke test

**Adds:** tests only.

1. **Idempotency:** run the chain twice over one document → identical row counts and ids.
2. **Crash recovery:** delete `enriched.json`, re-run → S1/S2 skip, S3 re-runs, result identical.
3. **Similarity smoke test:** ingest `clean_text.pdf`, embed a query semantically related to a known
   passage, run a raw `<#>` query, assert the expected chunk ranks first.

Test 3 is the one that matters most. It is the only evidence that Phase 1 produced *useful* data
rather than merely well-formed rows — wrong normalization, wrong dimension, and a misconfigured index
are indistinguishable from success without it.

**Done when:** all three pass, full suite green, `ruff check .` clean.

---

## Definition of done — Phase 1

1. `docker compose up -d` brings up eight healthy containers.
2. `alembic upgrade head` applies cleanly to an empty database.
3. Presigned upload → `POST /documents` → 202 with a `document_id`.
4. Re-uploading the same file returns 409 and publishes nothing.
5. The chain drives `QUEUED → COMPLETED` for every fixture except `encrypted.pdf`, which lands in
   `DEAD_LETTER` with a specific reason.
6. `parent_chunks` and `child_chunks` hold rows with non-null 1536-dim embeddings; `embedding` on
   `documents` no longer exists.
7. Re-running a completed document changes no rows.
8. The similarity smoke test ranks the expected chunk first.
9. Full suite green; `ruff check .` clean.
10. `app/core/` does not exist.

## Deferred to Phase 2

`app/core/` retrieval and generation, `POST /query`, citation assembly, reranking, streaming
responses, the evaluation harness, auth and multi-tenancy.

**The evaluation harness is the most consequential of these.** Until it exists, chunk sizes and
context prompts are tuned by intuition rather than measurement.
